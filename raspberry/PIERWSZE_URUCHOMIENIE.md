# Pierwsze uruchomienie — kartka kontrolna

- [ ] Raspberry Pi OS 64-bit z aktualnym systemem.
- [ ] Własny użytkownik, mocne hasło i SSH; brak domyślnego `pi`.
- [ ] Ethernet, oficjalny zasilacz, SSD USB 3.0 i UPS.
- [ ] Tunel Cloudflare wskazuje `http://localhost:8080`, a domena działa po HTTPS.
- [ ] Sprawdzony model oraz rozmiar SSD przed potwierdzeniem usunięcia.
- [ ] Hasło sejfu zapisane w menedżerze haseł.
- [ ] Klucz odzyskiwania zapisany poza Raspberry Pi w dwóch miejscach.
- [ ] `kla-status` pokazuje wszystkie pozycje jako `[OK]`.
- [ ] Logowanie i pobranie własnego dokumentu działa przez HTTPS.
- [ ] Zainfekowany/uszkodzony testowy upload jest odrzucany.
- [ ] SFTP używa osobnego konta i klucza z ograniczonym dostępem.
- [ ] `sudo edziennik-kla-backup --test-restore` kończy się wynikiem OK.
- [ ] Prawnik/IOD zatwierdził okresy w `/etc/kla/retention.env`.
- [ ] Klientka wie, kto odblokowuje serwer po pełnym restarcie.
